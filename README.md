# StrideCare — 뇌졸중 보행 정밀 계수

뇌졸중 환자의 **느린 보행**, **편마비 비대칭**, **발 끌기**, **지팡이 충격**, **몸통 흔들림**을 고려해 스마트폰 가속도·자이로 신호로 걸음 수를 세는 설치형 PWA입니다.

> **중요:** 이 앱은 의료기기가 아닙니다. 진단·치료·재활 처방을 목적으로 하지 않으며, 연구·재활 모니터링·선별 목적의 참고 도구입니다. 임상 판단과 치료 결정은 반드시 전문가가 수행해야 합니다.

---

## 1. 주요 기능

- **정밀 걸음 검출**: 중력 방향 투영 → 0.4–7 Hz 대역 통과 → 형태 기반 후보 점수 → 클러스터 억제 → 케이던스 적응형 불응기 → 누락 걸음 복구
- **좌우 비대칭 추정**: 골반 회전(수직 각속도)으로 좌/우 발을 구분하고, 계단시간 비대칭(%)과 걸음 리듬 그래프를 제공
- **실시간 계수**: 걸음 수, 케이던스, 신호 품질, 좌우 균형, 수직 가속도 파형, 관찰자 수동 계수
- **측정 프로토콜**: 자유 보행, 2분 보행(2MWT), 6분 보행(6MWT), 10m 보행
- **결과 분석**: 정밀 보정 전/후 걸음 수, 케이던스, 계단시간 비대칭, 걸음 변동계수, 보행 속도(추정 또는 10m), 품질 점수
- **관찰자 계수 검증**: Bland–Altman, MAPE, MAE, 편향, ICC(2,1), 일치 한계
- **개인 보정**: 관찰자가 직접 센 걸음 수를 기준으로 검출 임계값을 환자별로 조정
- **로컬 저장·CSV 내보내기**: 모든 기록은 기기 브라우저에만 저장되며 서버로 전송되지 않음
- **오프라인 사용**: 서비스 워커가 앱 셸을 캐시하여 네트워크 없이 실행
- **접근성**: 큰 글씨, 고대비, 애니메이션 줄이기, 48px 이상 터치 타깃

## 2. 빠른 실행

```bash
cd stridecare
python3 -m http.server 4173 --bind 127.0.0.1
# 브라우저에서 http://127.0.0.1:4173/ 열기
```

정확도 하네스(합성 보행 25회):

```bash
node tools/verify.mjs
```

마지막 실행 결과:

```text
MAPE 2.63%  max 10.4%  mean |asym err| 2.3pp
```

브라우저 UI에서도 **검증 → 브라우저에서 알고리즘 벤치마크 실행**으로 같은 25회 벤치마크를 실행할 수 있습니다.

센서 경로 배선 점검(모바일 UA + 50 Hz 합성 `devicemotion`):

```bash
node tools/sensor-e2e.mjs
```

이 하네스는 별도 헤드리스 Chrome을 띄워 센서 모드 시작 → 실시간 계수 → 결과 → 설정의 10초 센서 점검까지 확인합니다. 실제 하드웨어의 샘플레이트·권한·화면 잠금 동작은 실기기에서 최종 확인해야 합니다. Chrome 경로가 다르면 `CHROME_BIN` 환경 변수로 지정하세요.

### 휴대폰에서 실제 센서로 테스트하려면

동작 센서(DeviceMotion)와 서비스 워커는 **보안 컨텍스트**에서만 동작합니다.

- `localhost` / `127.0.0.1`: HTTP 허용
- 휴대폰에서 접속하는 LAN 주소: **HTTPS 필요**
- 배포: GitHub Pages, Netlify, Vercel 등 정적 HTTPS 호스팅에 `stridecare/` 폴더를 그대로 업로드

아이폰은 **Safari**, 안드로이드는 **Chrome**에서 가장 안정적으로 동작합니다. iOS는 첫 센서 사용 시 사용자 제스처(버튼 탭)를 통해 권한을 요청해야 합니다.

### 앱 설치

- **iOS Safari**: 공유 → 홈 화면에 추가
- **Android Chrome**: 주소창 메뉴 → 앱 설치 / 홈 화면에 추가

## 3. 사용 방법

1. **설정 → 환자 정보**에 이름/ID, 마비측, 보조기구, 키를 입력합니다.
2. 스마트폰을 **허리 벨트**에 단단히 고정합니다.
3. 측정 프로토콜을 선택하고 **측정 시작**을 누릅니다.
4. 걷는 동안 관찰자는 필요 시 **관찰자 계수** 토글을 켜고 실제 걸음 수를 탭합니다.
5. **측정 종료** 후 결과 화면에서 정밀 보정된 걸음 수와 지표를 확인합니다.
6. 관찰자 계수를 입력해 **비교하기**를 누르면 검증 대시보드에 반영됩니다. **기록 저장**을 눌러야 영구 저장됩니다.
7. 기록 화면에서 세션 상세를 열거나 CSV로 내보낼 수 있습니다.

측정 화면의 **개인 보정** 카드에서도 바로 보정을 시작할 수 있습니다. 보정에는 관찰자 계수가 필요하며, 30초 이상 보행을 권장합니다.

### 데모 모드

동작 센서가 없는 데스크톱/태블릿 브라우저에서는 **데모로 체험**을 선택할 수 있습니다. 데모는 합성 보행 신호이며 기록에는 항상 `DEMO` 태그와 `데모데이터=Y`가 붙습니다.

- 실제 측정 기록이 하나라도 있으면 기록·검증 대시보드의 대표 수치는 실제 기록만 사용합니다.
- 데모 기록만 있으면 호박색 경고와 함께 “데모 데이터 기준”임을 명시합니다.
- 데모로 만든 개인 보정은 저장되지만 **실제 센서 측정에는 적용되지 않습니다.**

## 4. 알고리즘 개요

일반 만보계는 100 steps/min 이상의 규칙적인 보행을 가정합니다. 뇌졸중 보행에서는 이 가정이 깨집니다.

| 문제 | 대응 |
|---|---|
| 느린 케이던스 (45–90 spm) | 0.4–7 Hz 대역 통과, 0.30–2.6 s 간격 허용 |
| 편마비로 약한 발 접지 | 피크 높이뿐 아니라 상승(pre-rise), 하중 골(post-trough), 골반 회전(yaw)을 함께 점수화 |
| 발 끌기·신발 끄는 소리 | 3–9 Hz 광대역 잡음을 억제하고, 수직 성분만으로는 약한 피크를 통과시키지 않음 |
| 지팡이 충격 | 260 ms 클러스터 억제 + 케이던스 기반 불응기 + 하중 골 형태 조건 |
| 몸통 흔들림 | 중력 벡터에 투영해 수평 성분을 제거 |
| 누락된 약측 걸음 | 인접 간격이 중앙값의 약 2배이면 중간 후보에서 누락 걸음을 복구 |

### 처리 순서

1. `accelerationIncludingGravity`를 중력 방향으로 투영
2. 0.4–7 Hz 대역 통과 필터(50 Hz 리샘플)
3. 후보 피크 추출 및 4개 특징(`zPeak`, `troughZ`, `riseZ`, `yawZ`) 계산
4. 260 ms 이내 피크를 하나의 클러스터로 억제
5. 케이던스 적응형 불응기(중앙 간격의 45%, 최대 550 ms) 적용
6. 1.55–2.60배로 벌어진 간격에서 누락 걸음 복구
7. 품질 점수(자기상관, 간격 CV, 충격 크기, 좌우 교대, 좌우 진폭비)와 좌우 배정

> 실시간 화면의 걸음 수는 확인 지연(0.55 s) 때문에 잠시 뒤처질 수 있습니다. **측정 종료 시 전체 녹음에 대해 정밀 보정 패스를 다시 실행**하므로 최종 결과가 실시간 값과 다를 수 있습니다.

## 5. 합성 벤치마크

`node tools/verify.mjs`는 5개 보행 유형 × 5개 시드 = 25개의 120초 합성 신호를 생성해 검출 성능을 측정합니다.

| 유형 | 특징 | 결과 |
|---|---|---|
| 정상 성인 | 110 spm, 대칭 | 오차 0.0% |
| 편마비 · 중등도 | 74 spm, 22% 비대칭, 약측 진폭 52% | 0.0–0.7% |
| 편마비 · 지팡이 | 58 spm, 지팡이 충격 | +3.5–4.4% (과검출) |
| 저측 · 끌기 | 88 spm, 강한 발 끌기 잡음 | −5.7–10.4% (과소검출) |
| 고령 · 서행 | 56 spm | 0.0–0.9% |

- **MAPE 2.63%**
- **최대 절대 오차 10.4%**
- **평균 비대칭 오차 2.3 percentage points**

가장 어려운 유형은 **저측·끌기 보행**으로, 발 끌기 잡음이 실제 약측 접지와 유사해 6–10% 과소검출이 발생합니다. 이는 합성 신호 결과이며 실제 환자 대상 임상 타당도 검증을 대체하지 않습니다.

## 6. 개인 보정

환자마다 신호 크기와 보행 패턴이 달라 단일 임계값으로는 부족할 수 있습니다.

1. **검증 → 보정 측정 시작**
2. 20–300초(권장 30–60초 이상) 동안 환자가 걷고, 관찰자는 앱 화면을 보지 않고 직접 걸음 수를 셉니다.
3. 녹음이 끝나면 관찰자 계수를 입력합니다.
4. 앱이 같은 녹음에 384개 이상의 임계값 조합을 적용해 관찰자 계수와 가장 가까운 조합을 찾습니다.
5. 오차가 개선되고 12% 이내일 때만 보정값을 저장합니다.

- 보정은 `zPeak`, `troughMin`, `scoreMin`, `fillTroughRatio`만 조정하며, 표준 설정에서 크게 벗어난 조합에는 정규화 페널티를 줍니다.
- 보정값은 브라우저 로컬 저장소에만 보관됩니다.
- **데모 보정은 실제 센서 측정에 적용되지 않습니다.**

## 7. 데이터·개인정보

- 모든 신호 처리와 저장은 **기기 내 브라우저**에서 수행됩니다.
- 측정 원신호는 저장하지 않고, 요약 지표와 최대 400개의 걸음 간격만 `localStorage`에 저장합니다.
- 서버 전송, 계정, 클라우드 동기화가 없습니다.
- CSV 내보내기는 사용자가 직접 실행할 때만 파일을 생성합니다.
- 브라우저 데이터를 삭제하면 기록도 사라집니다. 중요한 기록은 CSV로 백업하세요.
- 서비스 워커는 앱 셸과 Pretendard 폰트만 캐시하며, 측정 데이터를 캐시하지 않습니다.

## 8. 측정 불확실성과 한계

- **의료기기가 아닙니다.** 진단·치료 결정에 단독으로 사용하지 마세요.
- 지팡이·워커 충격은 실제 발 접지와 유사하게 보일 수 있습니다. 품질이 낮으면 관찰자 계수로 확인하세요.
- 스마트폰이 허리 벨트에 단단히 밀착되지 않으면 정확도가 떨어집니다.
- 트레드밀, 계단, 정지–출발이 반복되는 보행은 검증 범위 밖입니다.
- 한 세션 안에서 착용 위치를 바꾸지 마세요.
- 10m 보행 속도는 사용자가 정확히 10m에서 종료해야 합니다. 그 외 프로토콜의 속도는 키 기반 보폭 추정치입니다.
- 합성 벤치마크는 실제 환자 데이터의 대체물이 아닙니다. 임상 사용 전에는 관찰자 계수와의 동시 타당도 연구가 필요합니다.
- 센서 경로 E2E는 모바일 UA와 합성 이벤트로 배선을 검증하지만, 실제 iPhone·Android 기기의 센서 샘플레이트·권한·화면 잠금은 실기기에서 최종 확인해야 합니다.
- 낙상 위험이 있는 환자는 보호자·치료사가 함께 관찰해야 합니다.

## 10. 개발 메모

- 빌드 단계 없음. 순수 HTML/CSS/ES 모듈.
- `js/session.js`의 `SessionController`가 실시간 신호와 데모 재생을 동일한 시계로 처리합니다. 일시정지 시간은 `sessionNow()`에서 제외되어 녹음에 구멍이 생기지 않습니다.
- `detectSteps`는 최소 0.8초의 신호가 필요합니다.
- 실시간 트래커는 확인 지연(0.55 s) 이후의 걸음만 화면에 반영합니다.
- 최종 결과는 `StepTracker.finalize()`가 전체 녹음에 대해 누락 걸음 복구를 포함해 다시 계산합니다.
- 서비스 워커는 네트워크 우선, 실패 시 캐시 폴백입니다. 오프라인 프록시가 502를 반환하는 경우에도 캐시된 앱 셸을 사용합니다.
